Programación avanzada en shell

Curso 03-55 · Ramón M. Gómez Labrador · Universidad de Sevilla · Guía de scripting con BASH

1. Introducción

El intérprete de mandatos («shell») es la interfaz principal entre el usuario y el sistema. Es a la vez una interfaz de ejecución de órdenes y un lenguaje de programación que permite crear nuevas órdenes llamadas guiones o «shellscripts».

Hay dos familias de intérpretes en Unix: las basadas en Bourne (BSH, KSH, BASH) y las basadas en C (CSH, TCSH). El curso se centra en BASH (Bourne Again Shell), el más usado en Linux.

1.1. Características principales de BASH

  • Ejecución síncrona (una tras otra) o asíncrona (en paralelo).
  • Distintas redirecciones de entradas y salidas.
  • Control del entorno de los procesos.
  • Ejecución interactiva y desatendida, desde teclado o ficheros.
  • Órdenes internas para manipular el intérprete y su entorno.
  • Lenguaje de alto nivel: variables, operadores, matrices, control de flujo, entrecomillado, sustituciones y funciones.
  • Control de trabajos en primer y segundo plano.
  • Edición del histórico de mandatos.
  • Posibilidad de usar una shell restringida.

1.2. Cuándo utilizar el intérprete de mandatos

Su sintaxis es algo engorrosa pero fácil de aprender, y permite prototipar aplicaciones. No es adecuado para:

  • Procesos en tiempo real o donde la velocidad es fundamental.
  • Matemáticas de alta precisión, lógica difusa o números complejos.
  • Portabilidad entre plataformas.
  • Aplicaciones complejas o multihilo, o críticas para el sistema.
  • Situaciones donde debe garantizarse seguridad e integridad.
  • Proceso intensivo de ficheros con acceso directo o indexado.
  • Matrices multidimensionales o estructuras de datos (listas, colas, pilas).
  • Gráficos, dispositivos, puertos o «sockets», y bibliotecas o código propietario.

2. Modos de operación

2.1. La línea de mandatos

Mandato [Modificador ...] [Parámetro ...]
# Esto es un comentario
ls -al # lista el directorio actual
cd /var/log; grep -i error *     # varias órdenes con ;
find /tmp /var/tmp ! -user root -type f \
   -perm +2 -print               # \ continúa en la línea siguiente

2.2. Edición y ejecución de un guión

Un guión es un fichero de texto con líneas de mandatos que se ejecutan en secuencia. Se necesita permiso de escritura para crearlo o modificarlo y permiso de ejecución para lanzarlo. Si está en un directorio del PATH, basta el nombre.

vi prueba.sh          # o cualquier editor
chmod u+x prueba.sh   # activa el permiso de ejecución
./prueba.sh           # ejecuta el guión
prueba.sh             # si está en un directorio de $PATH
. miprofile           # el punto exporta las variables al entorno del usuario

Un script debe empezar con #! indicando el intérprete (BASH, BSH, PERL, AWK…):

#!/bin/bash
# ejemplo1: informe de la capacidad de la cuenta
echo "Usuario: $USER"
echo "Capacidad de la cuenta en KB:"
du -ks $HOME

2.3. Recomendaciones de programación

  • Código legible, con espacios y sangrías.
  • Comentarios sobre autor, descripción, uso, versión y fechas de modificación, y sobre bloques importantes.
  • Incluir ayuda sobre la ejecución y procesar bien los parámetros.
  • No escribir código enrevesado para ahorrar líneas; usar funciones y estructuras adecuadas para no repetir código.
  • Nombres descriptivos, ni muy largos ni muy cortos, sin confundirlos con mandatos. Funciones y programas en minúsculas; variables en mayúsculas.

3. Redirecciones

Unix hereda de C tres ficheros especiales: entrada estándar (descriptor 0, teclado), salida estándar (1, pantalla) y salida de error (2, pantalla). Los descriptores 3 al 9 permiten abrir otros archivos. /dev/null descarta datos.

3.1. Redirección de entrada

[N]<Fichero
miproceso.sh < fichdatos

3.2. Redirecciones de salida

RedirecciónDescripción
[N]> FicheroAbre para escritura (por defecto N=1). Si existe, se borra; si no, se crea.
[N]>| FicheroComo el anterior, pero el fichero debe existir previamente.
[N]>> FicheroAñade datos al final sin borrar el contenido.
&> FicheroSalida normal y de error en el mismo fichero.
configure > aplic.sal
make >> aplic.sal
make install >> aplic.sal

3.3. Combinación de redirecciones

Se interpretan de izquierda a derecha.

ls -al /usr /tmp /noexiste >ls.sal 2>ls.err
find /tmp -print >find.sal 2>/dev/null
RedirecciónDescripción
[N]<&MDuplicar descriptor de entrada M en N (N=0 por defecto).
[N]<&-Cerrar descriptor de entrada N.
[N]<&M-Mover descriptor de entrada M en N, cerrando M.
[N]>&MDuplicar descriptor de salida M en N (N=1 por defecto).
[N]>&-Cerrar descriptor de salida N.
[N]>&M-Mover descriptor de salida M en N, cerrando M.

Estas dos líneas son equivalentes; las dos dos siguientes no lo son, porque el orden importa:

ls -al /var/* &>ls.txt
ls -al /var/* >ls.txt 2>&1
ls -al * >ls.txt 2>&1   # normal y error a "ls.txt"
ls -al * 2>&1 >ls.txt   # el error va a la salida anterior, la estándar a "ls.txt"

3.4. Redirección de entrada/salida

[N]<>Fichero
echo 1234567890 > fich   # genera el contenido
exec 3<> fich             # abre "fich" con descriptor 3 en E/S
read -n 4 <&3            # lee 4 caracteres
echo -n , >&3           # escribe una coma
exec 3>&-               # cierra el descriptor 3
cat fich                  # => 1234,67890

3.5. Documento interno

Usa parte del propio script, hasta un delimitador, como entrada. El texto es literal (sin sustituciones ni expansiones). Con <<- se eliminan los tabuladores iniciales; con << se mantienen.

<<[-] Delimitador
   Texto
   ...
Delimitador

3.6. Tuberías

Usan la salida normal de un programa como entrada de otro: Mandato1 | Mandato2 ...

FiltroDescripción

4. Variables

BASH no distingue tipos: las variables son esencialmente cadenas, aunque según el contexto se usan como enteros o en condiciones. Se asignan con = y se consultan con $. Por convención se escriben en mayúsculas.

VAR1="Esto es una prueba"
VAR2=35
echo $VAR1          # => Esto es una prueba
echo "VAR2=$VAR2"   # => VAR2=35
ERR=2
echo ERR            # => ERR
echo $ERR           # => 2
echo ${ERR}         # => 2 (equivalente; útil para evitar confusión)

4.1. Tipos de variables

  • Locales: definidas por el usuario, dentro de un bloque, función o guión.
  • De entorno: afectan al comportamiento del intérprete y de la interfaz. Se exportan con export y las heredan los procesos hijos.
  • Parámetros de posición: los recibidos por un programa o función.
  • Especiales: sintaxis especial, referidas a valores internos del proceso.

4.1.2. Variables de entorno principales

PATH=$PATH:/home/cdc/bin:/opt/oracle/bin   # ejercicio propuesto

Seguridad: usar siempre caminos absolutos en PATH y nunca incluir el directorio actual (.) ni el padre (..). Declarar IFS como solo lectura para evitar «caballos de Troya».

4.1.3. Parámetros de posición

$0 es el nombre del programa, $1 el primer parámetro; a partir del décimo se usa ${10}. shift desplaza la lista hacia la izquierda.

grep "^$1:" /etc/passwd
grep ":$GID:" /etc/group | cut -f1 -d:

# mayusculas – convierte a mayúsculas usando ficheros o stdin
cat "$@" | tr 'a-zñáéíóúü' 'A-ZÑÁÉÍÓÚÜ'

4.2. Matrices

Se declaran con declare -a. BASH solo admite una dimensión, con índice numérico sin restricciones de tamaño ni continuidad. [@] o [*] se refieren a todos los valores.

declare -a NUMEROS
NUMEROS=( cero uno dos tres )
echo ${NUMEROS[2]}                    # => dos
NUMEROS[4]="cuatro"
NUMEROS=( [6]=seis siete [9]=nueve )  # celdas 6, 7 y 9
echo ${NUMEROS[7]}                    # => siete

4.3. Configuración del entorno

El administrador define el perfil global (/etc/bashrc) y ejecuta los ficheros de /etc/profile.d (.sh para shells tipo Bourne, .csh para tipo C). Cada usuario puede personalizar su perfil en ~/.bash_profile.

5. Expresiones

Categorías: aritméticas (resultado entero o binario), condicionales (cierto o falso) y de cadenas. Se evalúan de izquierda a derecha; los paréntesis tienen mayor prioridad.

5.1. Expresiones aritméticas

Se evalúan con let, solo con enteros de longitud fija (sin comprobar desbordamiento). La división por 0 genera un error procesable. Prioridad y asociatividad como en C: post/pre-incremento, signo, negación (! ~), **, * / %, + -, desplazamientos, comparaciones, igualdad, & ^ |, && ||, ternario E1 ? E2 : E3, asignaciones y coma.

let a=5
let b=$a+3*9              # b=32
let c=$b/($a+3)           # c=4
let a+=c--                # a=9, c=5
let CTE=$b/$c, RESTO=$b%$c   # Cociente=6, Resto=2
let N=59        # decimal
let N=034       # octal
let N=0x34AF    # hexadecimal
let N=20#G4H2   # base 20 (de 2 a 64)

Las evalúan los mandatos tipo test. Admiten negación (! Expr) y combinación con && y ||.

6. Entrecomillado y expansión

6.1. Entrecomillado

Modifica o elimina el significado especial de los metacaracteres. Tres tipos:

  • Escape (\): mantiene el valor literal del carácter siguiente; al final de línea continúa la orden.
  • Comillas simples: conservan el valor literal de todos los caracteres.
  • Comillas dobles: literal, salvo $, ` y \.

$"Cadena" se usa para traducción según LANG.

echo Hola; echo que tal        # dos órdenes
echo "Hola; echo que tal"      # => Hola; echo que tal
echo "Sólo con permiso \"root\""   # => Sólo con permiso "root"
echo 'Sólo con permiso \"root\"'   # => Sólo con permiso \"root\"

6.2. Expansión

BASH tiene ocho expansiones, en este orden: llaves, tilde, parámetro/variable, sustitución de mandato, aritmética, sustitución de proceso, división en palabras y expansión de fichero.

6.2.1. Llaves

[Pre]{C1,C2[,...]}[Suf]
echo a{b,c,d}e                # => abe ace ade
mkdir $HOME/{bin,lib,doc}

6.2.2. Tilde

~[Usuario] directorio personal (sin nombre, $HOME); ~+ directorio actual ($PWD); ~- directorio anterior ($OLDPWD).

ls -ld ~$1
du -ks ~$1
alias cda='cd ~-'   # en ~/.bashrc

6.2.3. Parámetro o variable

FormatoDescripción
${!Var}Expansión indirecta.
${Parám:-Val}El parámetro; si es nulo, el valor por defecto.
${Parám:=Val}Si es nulo, se le asigna el valor y se expande.
${Parám:?Cad}Si es nulo, mensaje de error.
${Parám:+Val}Valor alternativo si el parámetro no es nulo.
${Parám:Inic[:Long]}Subcadena.
${!Pref*}Nombres de variables con ese prefijo.
${#Parám}, ${#Matriz[*]}Tamaño en caracteres o en elementos.
${Parám#Pat} / ##Quita el patrón mínimo / máximo por el principio.
${Parám%Pat} / %%Quita el patrón mínimo / máximo por el final.
${Parám/Pat/Cad} / //Reemplaza la primera / todas las coincidencias.
USUARIO=${1:-`whoami`}
ANCHO=${COLUMNS:-80}
: ${1:?"Error: $0 fichero"}
EXT=${FICHERO##*.}            # extensión
RPM=${FICHRPM%.rpm}           # quita ".rpm"
CARACTERES=${#CLAVE}
NUEVO=${ANTIGUO/enero/febrero}
matriz[${#matriz[*]}]="nuevo" # añade un elemento
# Ejercicios:
DATOS=`ls -ld $1`; TIPO=${DATOS:1}; PERM=${DATOS:2:9}
if [ ${#OPCIONES} -gt 1 ]; then ...
f="$f${1%$e}"

6.2.4. Sustitución de mandato

$(Mandato) o `Mandato` sustituyen el mandato por su salida normal.

#!/bin/bash
# infous – lista información de un usuario. Uso: infous usuario
TEMPORAL=`grep "^$1:" /etc/passwd 2>/dev/null`
USUARIO=`echo $TEMPORAL | cut -f1 -d:`
echo "Nombre de usuario: $USUARIO"
echo -n "Identificador (UID): "
echo $TEMPORAL | cut -f3 -d:
GID=`echo $TEMPORAL | cut -f4 -d:`
grep ":$GID:" /etc/group | cut -f1 -d:
ls -ld `echo $TEMPORAL | cut -f6 -d:`
# Ejercicio:
echo "`basename $0`: \"$USER\" sin permiso de ejecución." >&2

6.2.5. Aritmética

$((Expresión))   o   $[Expresión]
ESPACIOS=$(( (ANCHO-${#CADENA})/2 ))
if [ ${#cad} -lt $[${#1}-1] ]; then ...   # ejercicio

6.2.6. Sustitución de proceso

Usa un fichero especial de tipo cola (FIFO) para intercambiar datos entre dos procesos: <(Lista) hace que la lista de órdenes escriba en un fichero que otro proceso puede leer; >(Lista) pasa lo escrito en el fichero como entrada a la lista.

6.2.7. División en palabras

El intérprete divide la línea usando los caracteres de IFS. Varios separadores seguidos cuentan como uno. Por seguridad el administrador debe declarar IFS de solo lectura. Así, du -ks $HOME se divide en «du», «-ks» y «/home/ramon».

6.2.8. Expansión de fichero

* cualquier cadena (incluida la nula); ? un único carácter; [Lista] cualquier carácter de la lista (rangos con -; si empieza por ^, los que no estén en ella). El resultado se ordena alfabéticamente.

ls *.rpm
ls [a-z]*.rpm
ls .[bxX]*
ls *.??
cd /var/log; tar cvf copialog.tar syslog.[0-9] messages.[0-9]   # ejercicio

7. Programación estructurada

7.1. Listas de mandatos

ListaDescripción
Mandato &Ejecuta en segundo plano (no debe ser interactivo).
Man1 | Man2Tubería; cada mandato es un proceso separado.
Man1; Man2Varios mandatos en la misma línea.
Man1 && Man2Ejecuta Man2 si Man1 termina con éxito (estado 0).
Man1 || Man2Ejecuta Man2 si Man1 falla.
(Lista)Lista en un subproceso.
{ Lista; }Bloque ejecutado en el propio intérprete.
\Continúa la orden en la línea siguiente.
/sbin/convertquota -u / && rm -f /quota.user
grep 'hid' /proc/bus/usb/drivers || modprobe hid 2> /dev/null
# Ejercicio:
loadkeys $KEYMAP < /dev/tty0 > /dev/tty0 2>/dev/null && \
   success "Loading def keymap" || failure "Loading def keymap"

7.2. Condicionales y selectivas

7.2.1. if

Solo hay un fi por bloque. Si se escribe en una línea, el ; va antes de then, else, elif y fi. La condición puede ser el código de salida de un mandato o una expresión de test entre corchetes [ Condición ].

if Expresión1; then
   Bloque1
[elif Expresión2; then
   Bloque2 ...]
[else BloqueN]
fi

if [ $RESULT -gt 0 ]; then rc=1; fi

if [ -f /etc/sysconfig/network ]; then
   . /etc/sysconfig/network
else
   NETWORKING=no
fi

if [ "$rc" = "0" ]; then
   success "$STRING"; echo
elif [ "$rc" = "1" ]; then
   passed "$STRING"; echo
fi

7.2.2. case

Los patrones se comprueban en secuencia y solo se ejecuta el primero que coincida. Se admiten comodines; el patrón por defecto es *. Varios patrones se separan con |. Cada bloque acaba en ;;.

case Variable in
   [(]Patrón1) Bloque1 ;;
   ...
esac

case "$UTC" in
   yes|true) CLOCKFLAGS="$CLOCKFLAGS --utc" ;;
   no|false) CLOCKFLAGS="$CLOCKFLAGS --localtime" ;;
esac

7.3. Bucles

Todo bucle necesita condición de salida. break rompe el bucle y continue salta a la condición; ambos deben evitarse en programación estructurada.

7.3.1. for

Itera por cada palabra de una lista (si se omite, por cada parámetro posicional). También existe la forma de estilo C con tres expresiones aritméticas: inicial, condición y actualización.

for Var [in Lista]; do
   Bloque
done

for ((Exp1; Exp2; Exp3)); do
   Bloque
done

for library in /lib/kernel/$(uname -r)/libredhat-kernel.so* ; do
   ln -s -f $library /lib/
   ldconfig -n /lib/
done

for (( times = 1; times < 20; times++ )); do
   /usr/sbin/rpcinfo -p | grep ypbind > /dev/null 2>&1 && \
   ypwhich > /dev/null 2>&1
done

7.3.2. while y until

while repite mientras la condición sea cierta; until, hasta que lo sea. Conviene usar el que dé la condición más sencilla, evitando expresiones negativas.

while [ $# != 0 ] ; do
   processdir "$1"
   shift
done
Ejercicio propuesto: convertir este bucle while en until y en un for de estilo C. 
i=5
while [ $i -ge 0 ] ; do
   if [ -f /var/log/ksyms.$i ] ; then
      mv /var/log/ksyms.$i /var/log/ksyms.$(($i+1))
   fi
   i=$(($i-1))
done

7.3.3. select

Muestra un menú interactivo y ejecuta el bloque de la opción elegida hasta un break. Sin lista usa los parámetros posicionales. El indicativo es PS3. Se usa poco.

select Var [in Lista]; do
   Bloque
done

8. Funciones

Una función es código declarado antes de usarse, que recibe parámetros y se puede llamar tantas veces como haga falta. Dentro, los parámetros son $0, $1… como en el programa principal. Devuelve un valor numérico con return [Valor]. Las variables declaradas con local son internas a la función (lo que permite recursividad); las demás son globales.

[function] NombreFunción ()
{
   Bloque
   [ return [Valor] ]
}
NombreFunción [Parámetro1 ...]

Ejemplo completo (comprus):

#!/bin/bash
# comprus - comprueba la existencia de usuarios en listas y en
# el archivo de claves (normal y NIS).
# Uso: comprus ? | cadena
# Ramón Gómez - Septiembre 1.998.

# Rutina de impresión. Parámetros:
# 1 - texto de cabecera. 2 - cadena a buscar. 3 - archivo.
salida ()
{
   if egrep "$2" $3 >$TMPGREP 2>/dev/null; then
      echo " $1:"
      cat $TMPGREP
   fi
}

## PROGRAMA PRINCIPAL ##
TMPGREP=/tmp/grep$$
DIRLISTAS=/home/cdc/listas
if [ "x$*" = "x?" ]; then
   echo "
Uso: `basename $0` ? | cadena
Propósito: Búsqueda de usuarios.
   cadena: expresión regular a buscar.
"
   exit 0
fi
if [ $# -ne 1 ]; then
   echo "`basename $0`: Parámetro incorrecto." >&2
   exit 1
fi
for i in $DIRLISTAS/*.lista; do
   salida "$1" "`basename $i | sed 's/.lista//'`" "$i"
done
salida "$1" "passwd" "/etc/passwd"
[ -e "$TMPGREP" ] && rm -f $TMPGREP
Ejercicios propuestos: (1) una función que reciba una cadena y muestre su último carácter (el primero tiene índice 0); (2) una función que imprima una cadena centrada en pantalla, usando COLUMNS o 80 columnas por defecto.

9. Características especiales

BASH añade: opciones de llamada, programas interactivos, control de trabajos y señales, personalización del indicativo, alias, histórico, edición de línea, pila de directorios, intérprete restringido y modo compatible POSIX 1003.2.

9.3. Intérprete de uso restringido

Se ejecuta con rbash, bash -r o bash --restricted. En este modo:

  • No se puede usar cd.
  • No se pueden modificar SHELL, PATH, ENV ni BASH_ENV.
  • No se pueden ejecutar mandatos indicando su camino; solo los de los directorios fijados por el administrador.
  • No se admiten caminos como argumento de ..
  • No se pueden añadir funciones en los ficheros de inicio.
  • No se admiten redirecciones de salida.
  • No se puede usar exec para reemplazar el intérprete.
  • No se pueden añadir o quitar mandatos internos.
  • No se puede salir del modo restringido.
